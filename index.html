ByteFolk · Digital Employee Marketplace

数字员工交易平台 · 功能图

一个买方可以发现已发布的员工版本、下单并授权一次运行， 并让该订单去驱动既有的 Runner / Quote / Credit 链路，按买方自己的 Credit 账户计费。 平台不运行员工、不持有 Agent Host 凭据、 也不自行判定一次运行可计费。

02域模块

交易平台的四个有界模块。每个模块只承接父记录 #12 中属于自己的那几条需求，归属到对应的子记录。

C1

租户主体

src/catalog/principal.ts

CatalogPrincipal 绑定租户、主体、buyer/seller 角色与操作白名单。身份只来自服务端校验——请求体、请求头、客户端声明的身份一律不认。任何畸形字段统一报 invalid_principal，不泄露是哪个字段错了。

归属 #14 · REQ-001 / AC-001
C2

Listing 版本

src/catalog/listing.ts

ListingCatalog 维护 append-only 的不可变版本。一个版本把 (employeeId, employeeVersion, packageDigest, engine) 绑到恰好一版 RateCard，并带一个 recordDigest。改价或换包只产生新版本，绝不改动旧版本。

归属 #15 · REQ-002 / REQ-006
C3

订单生命周期

src/catalog/order.ts

OrderBook 提供显式状态机、payload 绑定的幂等键、不可逆终态，以及 OrderAuthorization——其 authorizationDigest 就是那个不可变的、买方可见的放行授权。

归属 #16 · REQ-003 / REQ-005
C3

放行授权器

src/catalog/release-authorizer.ts

CatalogReleaseAuthorizer 实现了 ReleaseAuthorizer 端口——docs/architecture.md 里记着"仍然缺失"的那一个。它只在持久化的、买方绑定的、未过期订单与传入的 Quote / 版本 / 包摘要 / 引擎逐项精确匹配时放行。

03订单状态机

有界、显式枚举、终态不可逆。点击状态查看它的含义。

created

点击任一状态查看说明。后三个均为终态——一旦进入就不可再变更，重复授权会被拒绝。

04放行拒绝矩阵

授权器不接受调用方提供的摘要，也没有宽松默认值。除了精确匹配之外，每一条路径都会带一个稳定的原因码被拒绝。

authorization_not_recorded

订单从未被授权，或找不到对应的授权记录。

quote_mismatch

传入的 Quote 与该订单绑定的 RateCard 快照不一致。

employee_mismatch

员工 ID 或版本号与该订单所依据的 listing 版本不一致。

package_digest_mismatch

包摘要不一致——要跑的东西和买方下单时的不是同一个。

engine_mismatch

执行引擎与 listing 版本声明的不一致。

authorization_expired

订单或授权已过期，由服务端时钟判定，绝不信客户端时间。

05平台边界

这条边界是这个平台的立身之本：可选的控制面，而不是第二个 Agent 运行时。

平台负责
  • 在 API 边界认证租户与买卖方身份
  • 维护 listing 的不可变版本与其 RateCard 绑定
  • 驱动订单生命周期并产出不可变授权摘要
  • 按持久化的买方授权放行一次运行
  • 产出授权证据，供既有 Runner / 账务内核消费
平台绝不
  • 运行员工、Agent Host、模型循环或 MCP 进程
  • 存储或分发包体，解析本地包路径
  • 持有 Host / 模型凭据
  • 写 Credit、预留、结算、应收或任务 / 尝试 / 回执状态
  • 接受调用方提供的摘要，或自行判定一次运行可计费
  • 做支付收款、卖家出款、税务、退款或纠纷处理

07当前实现到哪一步

这是一张功能图，也是一份范围声明。PR #13 落地的是内存参考实现：域模型、状态机、授权器与端到端闭环都已完成并有测试覆盖，但下面这些还没有落地，页面上所有标为未落地的步骤都属实：
  • 持久化与迁移——29 张既有表里没有 listing / order / tenant / buyer，需要新迁移；编号需避开被 M3 预留的 005。
  • 面向买方的 HTTP API——目前只能在进程内构造命令调用。
  • 网关签名断言适配器——租户主体沿用既有的签名断言纪律，但适配器尚未接上。
  • M3 的信任权威仍然是 HOLD 状态，本平台只产出授权证据，不是计费权威。
